# Етапи обробки одного кадру, зображення для презентації

Два набори, по одному кадру з середини польоту. На обох у кадрі є і об'єкти, і
небо, на `run1` додатково видно лопаті гвинтів у нижніх кутах.

| набір | кадр | що показує |
|---|---|---|
| `euroc` | `1775034831515681460.png` | метод працює: похибка глибини від 2,72 м до 0,77 м |
| `run1` | `1787595584854525184.png` | метод не працює і сам це бачить: похибка від 0,85 м до 4,83 м, зате вага довіри падає |

Пара DPVO + ZoeDepth, таблиця корекції `loo_<набір>_zoedepth.npz`, навчена без
цього ж набору.

## Файли

```
presentation_frames/<набір>/
    01_frame.png          вхідний кадр камери
    02_fde_raw.png        сира глибина ZoeDepth
    03_err_raw.png        |z − z_ет|, похибка сирої глибини
    04_vslam_points.png   кадр з опорними точками VSLAM, колір за глибиною
    05_scale_s.png        множник калібрування s по ділянках
    06_err_calib.png      |z′ − z_ет|, похибка після таблиці і калібрування
    07_weight_w.png       вага довіри w, відкинуті пікселі білі
    08_prob_frame.png     внесок кадру в карту, P = sigmoid(0,85 · w)
    stats.txt             числа для цього кадру
    _dump/ _prob/ _grid/  проміжні файли прогону, з яких усе зроблено
```

Усі зображення рівно 640 на 480 пікселів.

## Шкали

Однакові для обох наборів, щоб рисунки можна було класти поруч.

| що | шкала | колірна карта |
|---|---|---|
| глибина (02) | від 0 до 50 м | turbo, темно-червоне понад 50 |
| похибки (03 і 06) | від 0 до 20 м, **спільна** | magma, салатове понад 20 |
| множник s (05) | від 0,5 до 2, центр у 1 | coolwarm |
| вага w (07) | від 0 до 1 | viridis |
| P кадру (08) | від 0,50 до 0,70 | RdYlGn_r |

Біле на 03, 06, 07 і 08 означає, що там немає числа: на похибках це відсутність
еталона, тобто небо, на вазі і на ймовірності це відкинутий піксель.

Верхня межа шкали ймовірності не 1, а 0,70, бо один кадр вносить
`P = sigmoid(0,85 · w)` при `w` від 0 до 1 і фізично не може дати більше.

## Як відтворити

```bash
cd src && source ../.venv/bin/activate

# 1. прогін із збереженням саме цього кадру
python3 occupancy_3d_map.py --mode dataset \
    --dataset_root ../datasets/euroc/2026-04-01_12-13-18_000_quadrotor \
    --vslam_dir ../results/euroc/dpvo --fde_dir ../results/euroc/zoedepth \
    --depth_refiner ../refiners/loo_euroc_zoedepth.npz \
    --output_dir ../presentation_frames/euroc/_grid \
    --dump_intermediate ../presentation_frames/euroc/_dump \
    --prob_maps ../presentation_frames/euroc/_prob \
    --dump_frame_name 1775034831515681460.png --n_frames 80

# 2. вісім PNG і stats.txt
python3 presentation_frames.py --dataset euroc
```

Для `run1` те саме з `--dataset_root ../datasets/run1`, своїм VSLAM, своєю
таблицею і кадром `1787595584854525184.png`.

Прапорець `--dump_frame_name` додано саме для цього. Без нього дамп бере кадри
за сталим кроком і на потрібний не потрапляє. Кадр додається у вибірку в
хронологічному порядку, тому самоналаштовні масштаби до нього прогріті так
само, як у звичайному прогоні, а не взяті з першого кадру.
